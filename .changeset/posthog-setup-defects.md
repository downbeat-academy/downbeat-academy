Fix three defects in the PostHog setup that was generated by the PostHog wizard.

- Exclude `/ingest` from the `proxy.ts` matcher. The proxy runs `auth.api.getSession()` — a
  database round trip — on every path it matches, so every analytics event and every proxied
  PostHog asset was triggering one, including for anonymous visitors.
- Gate initialisation on the production hosts via `shouldInitPostHog`, mirroring Fathom's
  `includedDomains`. Local development and preview deploys were writing into the same PostHog
  project as production, making the data impossible to trust. `NEXT_PUBLIC_POSTHOG_DEBUG=true`
  is the documented escape hatch for verifying instrumentation locally.
- Turn off PostHog's `capture_exceptions`. Sentry is the system of record for errors; both were
  capturing every exception.

Also renames `getPostHogClient` to `createPostHogClient`, which is what it has always done — it
constructs a new client per call rather than returning a cached one.
